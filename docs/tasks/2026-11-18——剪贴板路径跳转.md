# 剪贴板路径跳转（Goto Path from Clipboard）

独立于 bridge / 会话 / TUI。从系统剪贴板读一段文本，若能解析成**恰好一条**文件位置，则在当前项目里打开并尽量落到行/列。挂在本插件只为复用 keymap 分组和安装面，不读写 pi 协议。

本文是实施 spec。实现：`ClipboardPathParser`、`OpenClipboardPathAction`（`Pi.OpenClipboardPath`）。

## 1. 产品

- **Action id：** `Pi.OpenClipboardPath`
- **文案：** `Open Path from Clipboard` / `从剪贴板打开路径`
- **分组：** Keymap → Pi Terminal Bridge。不进编辑器右键（避免和 Send to Pi 抢菜单）。
- **默认快捷键：** `Ctrl+Alt+Shift+P`。现有 `Ctrl+Shift+P` / `Alt+Shift+3` 不动。
- **可见性：** 有 `Project` 就显示；剪贴板不像路径时 **disable**（update 里判断），不要弹窗报「不是路径」。
- **设置页：** 不增加选项。

成功：打开编辑器，能解析出行则落到该行（1-based），有列则落到该列（1-based，钳到行长）。失败：状态栏一句，不抢焦点、不 baloon。

## 2. 非目标

- 不解析多段路径列表、diff、整段 JSON、邮件正文。
- 不把失败变成 Find in Files（那是搜内容）。多个候选文件用短列表选择，零候选只提示。
- 不读 Terminal 选区、不读 OSC 8、不改 pi extension、不加 v2 事件。
- 不实现「点击消费剪贴板」的全局手势。
- 不打开目录当文件（目录：状态栏说明，结束）。

## 3. 「有且只有一个路径」

剪贴板字符串经规范化后，必须能抽出 **一个** `(path, line?, column?, endLine?)`。否则 action 视为不适用。

规范化（按序，全部幂等）：

1. 只取 `DataFlavor.stringFlavor`。文件列表 flavor（从 Finder/Explorer 复制的真实文件）另走：若恰好一个 `File` 且是普通文件，直接打开，行号空。多个文件 → disable。
2. 去掉 BOM；统一 `\r\n` / `\r` 为 `\n`；`trim()`。
3. **整段只能是一行。** 含未修剪掉的换行 → 不是「只有一个」（用户复制了代码块）。
4. 剥一层包裹（有则剥一次）：成对 `"…"` / `'…'` / `` `…` `` / `<…>` / `(…)`；前缀 `at `（忽略大小写）。
5. 去掉首尾反引号残留、末尾英文逗号/分号/句号（`.,;`）。
6. 剥 `file://` / `file:`（含 `file:///C:/`、`file://localhost/`）。URL decode。
7. Windows `file:///` 盘符、WSL `\\wsl$\…` / `//wsl.localhost/…` 保留为本地绝对路径语义。
8. 展开前缀 `~` / `~/` 为用户 home（`System.getProperty("user.home")`），只认路径开头的 `~`。

剥完后若为空、或仍含空白（路径中间空格：仅当整段被引号包过且第 4 步已剥，才允许空格；否则空白 → 不适用），进入解析。

## 4. 位置语法（从右往左剥）

`path` 上可叠加 **一种** 位置后缀，冲突时只认最右边那组。行号 1-based，列可选。`endLine` 只用于打开时落到 start（不选区），解析保留以便以后扩展。

| 形态 | 例 | 语义 |
|---|---|---|
| `:line` | `Foo.kt:76` | 行 76 |
| `:line:column` | `Foo.kt:76:12` | 行 76 列 12 |
| `:line-end` | `Foo.kt:76-90` | 行 76（end 忽略） |
| `:line-end:column` | 不支持，避免和 Windows 盘符歧义 | — |
| `#Lline` / `#Lline-end` | `Foo.kt#L76`、`@src/a.go#L10-25` | 与 `PiFileRefs` 输出对齐 |
| `#line=n` 查询 | `Foo.kt#line=76` | 少见，认 |
| `(line:col)` 编译器尾 | `Foo.kt(76,12)` / `Foo.kt(76:12)` | 行/列 |
| Windows 盘符 | `C:\a\b.kt:76` | `C:` 不是行号；行号仍从右边 `:\d` 剥 |

剥位置时：

- 先匹配 `#L\d+(-\d+)?` 或 `#line=\d+`。
- 再匹配 `\(\d+[,:]\d+\)$`。
- 再匹配 `:(\d+)(?::(\d+))?$` 或 `:(\d+)-(\d+)$`。
- **Windows：** `^[A-Za-z]:\\` 或 `^[A-Za-z]:/` 开头时，第一个 `:` 不参与行号。`C:76` 这种两段式 **不是路径**。
- 行/列 ≤ 0 或明显越界数字（如 9 位）→ 丢掉位置，仍当纯路径。

`@` 前缀（`@src/foo.kt#L10`）在剥位置之前去掉一个前导 `@`，与面板引用一致。

## 5. 认可的路径形态（剥位置之后）

任一即「像路径」：

1. 绝对 Unix：`/` 开头。
2. 绝对 Windows：盘符 + `\` 或 `/`；UNC `\\server\share\…`。
3. `file:` 已在规范化里变成绝对本地路径。
4. 项目相对：含 `/` 或 `\` 的相对段（`src/a.kt`、`.\src\a.kt`、`../lib/a.kt`）。
5. **单段文件名** `Foo.kt`：仅当带位置后缀、或带扩展名、且项目内 **恰好一个** 同名文件时才算。无扩展名单段（`README` 除外：允许 `README`/`Makefile`/`Dockerfile`/`AGENTS.md` 等无后缀常见名）默认 **不像路径**，避免把普通单词当文件。
6. 含扩展名的相对单段 `foo.kt`：按第 5 条唯一性约束。

不像路径的例子（action disable）：`hello world`、`git commit -m`、URL `https://…`、纯数字、多行、空、两个逗号分隔路径。

## 6. 解析到 VFS

有 `Project`。顺序短路，命中普通文件即停：

1. **绝对路径** → `LocalFileSystem.refreshAndFindFileByPath`（正规化 `\`→系统分隔；不 follow 任意 symlink 出盘，只这一次 find）。
2. **相对 `project.basePath`** → 拼绝对路径再 find。`./` `.\` 去掉。
3. **相对当前编辑器文件的父目录**（若有 `CommonDataKeys.VIRTUAL_FILE` 且为本地文件）：解析 `../`。用于从 TUI 复制的相对片段。
4. **后缀匹配：** 把 path 正规成 `/` 分隔，在项目内容根里找 `relativePath` 以该后缀结尾的文件。0 个继续；1 个采用；≥2 个进入歧义。
5. **仅文件名：** `FilenameIndex.getVirtualFilesByName`（Dumb 时跳过索引，只做 1–4）。0 / 1 / ≥2 同上。

候选必须 `!isDirectory` 且（默认）在项目内容根内。**项目外绝对路径**仍打开（用户明确复制了 `/tmp/x`），走 `NonProjectFileWritingAccessProvider` 的既有「只读外部文件」提示，不要自己拦。

## 7. 打开

- 唯一文件：`OpenFileDescriptor(project, vf, line0, col0).navigate(true)`。无行：`line=0,col=0`（文件头）。行超出文档：落到最后一行。
- 歧义（≥2）：`JBPopupFactory` 文件列表（相对项目路径），选一项再打开；Esc 取消。不要静默打开第一个。
- 零候选：`WindowManager.getStatusBar(project).info = "No file for clipboard path"`（中文 UI 用 IDE bundle 或固定中英一句即可）。不抛 Dialog。
- `update()`：字符串 flavor 解析失败或「不像路径」→ `isEnabled=false`。解析成功但尚未 find（find 可能慢）→ **仍 enable**，把 IO/索引放到 `actionPerformed`；`update` 只做轻量正则/形态判断，线程 `BGT` 读剪贴板，`actionPerformed` 在 EDT 再读一次剪贴板以免竞态。

## 8. 与本插件的关系

- 新类建议 `actions/OpenClipboardPathAction.kt` + 纯 JVM 解析器 `clipboard/ClipboardPathParser.kt`（无 IntelliJ 依赖更好测：输入 string → `ParsedLocation`）。
- **不**调用 conversation / bridge / terminal。
- 解析器单测覆盖第 4–5 节表格（Gradle `test`，本地仍按仓库约定不主动 `./gradlew`）。
- README 配置表加一行：可选 keymap，剪贴板是单条路径时打开文件。发版时再写；本 spec 合入 `dev` 时按 AGENTS 同步中英 README。

## 9. 解析例

| 剪贴板 | 结果 |
|---|---|
| `src/main/kotlin/com/piterminal/bridge/PiSettings.kt:76` | 相对项目，行 76 |
| `@src/a.go#L10-25` | 相对，行 10 |
| `file:///home/u/proj/a.kt` | 绝对 |
| `C:\proj\a.kt:10:2` | Windows 绝对，行 10 列 2 |
| `` `PiSettings.kt:76` `` | 唯一文件名 + 行 |
| `read src/a.kt:76-90` | 不像「只有路径」→ disable |
| `https://github.com/foo` | disable |
| 两行路径 | disable |
| Finder 拖一个文件到剪贴板 | 打开该文件，无行号 |

## 10. 验收

- 项目内相对路径 + `:line` / `#L` / `:line:col` 各一次，光标行（及列）正确。
- Windows 盘符与 `:line` 同时存在时盘符不被吃成行号（有 Windows 再测；解析器单测必须覆盖）。
- 剪贴板是普通句子时动作灰掉，按快捷键无弹窗。
- 同名文件两个时弹出列表，不乱跳。
- 焦点在 Terminal / 面板输入框时快捷键仍触发（Action 不依赖 Editor DataContext）。
