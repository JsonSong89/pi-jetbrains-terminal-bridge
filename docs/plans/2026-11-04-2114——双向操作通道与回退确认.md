# 双向操作通道与回退确认

状态：收敛后的设计方案，尚未实现。取代本文件此前偏重自建会话状态机的草案。

**插件主体结构保持不变：IDEA Terminal 运行交互式 pi TUI，extension 在该 TUI 进程中执行操作。绝不切换到 pi RPC mode，也不额外启动 RPC 进程操作同一会话。** 只借鉴 RPC 的请求关联、响应与事件分离及 JSONL framing。

配套规范：[Bridge 与 extension 通信协议](../bridge-protocol.md)。协议字段、状态含义和开发者接入规则以该规范为准；本文件描述实施方案与业务行为。

## 1. 决策表

| 项目 | 收敛结论 |
|---|---|
| 产品架构 | 保持 IDEA + Terminal TUI + 托管 extension；不用 RPC mode |
| 控制操作 | 经双向 bridge，不再粘贴 rewind 命令到 Terminal 编辑器 |
| 会话权威 | pi 管理会话、持久化和分支；IDEA 消费 pi 原生条目构成的快照，不自行重建会话树 |
| 上下文 | 首次连接、重连、操作完成及主动查询返回完整活跃分支快照；先不做增量同步协议 |
| 本地数据 | IDEA 保留草稿、标题、面板隐藏记录和本地索引；它们不是 pi 会话事实 |
| 成功确认 | pi 执行并核验后返回结果及快照，IDEA 才提交本地业务变化 |
| 超时策略 | **用户已确认：结果未知、保留原状态、按同一 requestId 查询，绝不自动重放** |
| 公共封装 | Transport → OperationRuntime → PiAdapter；业务服务位于其上，不向公共协议加入 rewind/fork 专用状态 |
| 状态分离 | 执行状态、连接可达性、本地业务提交状态彼此独立；超时不能改写远端执行状态 |
| 版本 | bridge 协议版本、method 版本、pi/session 格式版本分别处理 |
| 首期交付 | 公共通道 + 快照 + rewind；以只读、同会话修改、替换会话三类契约验证扩展性 |
| fork | 后续添加 ForkWorkflow 与 executor，复用协议与交接能力；首期不宣称已迁移 fork |

### 1.1 核实的现状

基线代码 dev `672f934`：

- `PiConversationService.rewindConversation` 先裁消息和写草稿，再调用 sendText，无远端结果确认。
- sendText 是 bracketed paste + 80ms 后 Enter，不是可靠操作通道。
- bridge 当前是 extension→IDEA 的 v1 短连接事件，没有反向控制、能力握手或请求日志。
- endpoint 存在和 Terminal 存活都不能证明 extension 可执行操作。
- extension 用索引/文本定位，重复文本可能歧义；navigateTree 返回 cancelled 未检查；部分通知使用了非公开级别 `warn`。
- 当前 mock 测试只记录导航调用，未验证真实分支、取消、断联或重启恢复。
- 用户首次 rewind 未生效的具体原因仍未复现；不能断言是 Enter 被吞。

### 1.2 pi 能力边界

本机核对的是 pi 1.5.0 的安装文档和源码，不等于用户实际版本兼容证明：

- `pi.sendUserMessage('/内部命令', {expandPromptTemplates:true})` 可程序化分发注册命令；匹配后不发起模型请求。
- navigateTree/fork 需要 CommandContext；普通 socket 回调不直接调用它们，不缓存旧 ctx。
- InteractiveMode 的导航 wrapper 会更新 TUI；不得直接修改 SessionManager/jsonl 替代公开导航 API。
- fork 的 withSession 在旧实例 shutdown、新实例 session_start 之后运行，必须用新上下文。
- RPC mode 是独立 stdin/stdout 模式，本项目只借鉴其协议习惯。
- JSONL 是 framing，不是永远不变的 schema；原生 session 格式有版本，需要适配和兼容验证。

## 2. 对外契约

### 2.1 分层

| 层 | 职责 | 不应知道 |
|---|---|---|
| Transport | 认证、握手、连接、JSONL、有界读写、背压、心跳 | rewind、fork、草稿、归档 |
| OperationRuntime | 请求关联、去重、日志、查询、资源互斥、结果交接 | 面板如何裁剪、如何创建目标 Terminal |
| PiAdapter | 原生会话快照、命令派发、API 版本适配、后置核验、replacement 生命周期 | IDEA UI 组件 |
| ConversationOperations / ForkWorkflow | 发起意图、检查本地变化、提交视图、草稿保护、多阶段业务 | socket、帧格式、心跳、重连计时 |

`OperationHandle` 只提供 id、最后确认的执行状态、观察状态、结果订阅和只读查询。不提供自动 retryExecute。

注册指令需定义 method/version、参数/结果校验器、资源锁键、前置条件、executor 和结果核验。锁键使用稳定资源（如 tabKey），不能随 fork 的 sessionId 改变而丢失。

### 2.2 上下文与本地面板

- pi→IDEA：统一 SessionSnapshot，包含 session 身份、leaf、完整活跃分支的原生 entries、公开运行状态与采集标记。
- IDEA→pi：携带目标 entryId、观察到的 snapshot/session 和业务前置条件；可附定位上下文，但不是权威数据，不回写整个会话。
- UI 仍只展示用户消息；传输 AI/tool entries 是为了保留原生上下文，不要求把它们显示在面板。
- 原有“删除卡片不删除 pi 消息”保持不变：增加独立的本地隐藏 entry 集合，不能每次快照把已隐藏卡片恢复回来。
- 旧面板记录通过文本和顺序保守映射到 pi entryId，歧义时保留并提示，不猜 newest-first。新记录一旦确认绑定，使用 `(sessionId, entryId)`，不靠可变索引。
- 成功快照驱动面板更新；不再仅凭操作名推算 subList 裁剪。草稿仍由业务服务处理，revision 已变则不覆盖，提供待恢复文本入口。
- UNKNOWN 期间仍保留面板原状；新快照可用于对账展示，但不能把“当前状态像成功”当作该请求已成功。

### 2.3 稳固接口的验证标准

新增只读查询、修改模型或 rewind：仅增加 method descriptor、executor、业务处理及测试，不改帧类型或公共状态机。

新增 fork/switch：复用运行时交接功能，不再增加 fork_result 等专用消息。新增多阶段业务只增加 Workflow，不将 Terminal 启动逻辑放入协议。

## 3. 运行流程

### 3.1 通道建立

extension 主动连接现有 loopback server，v2 握手并声明经验证的 capabilities。v1 旧事件暂保留，但 v2 托管 tab 的会话状态由单一新入口提交，避免旧 session_changed 抢先归档/换绑。

先完成无副作用内部命令派发 probe，再开放修改能力。内部命令唯一命名，只接收已登记 requestId；保留前缀 input 拦截避免不兼容时落入模型 prompt。probe 失败禁用操作，不能退回粘贴命令。

首次/重连获取快照。socket 断开可自动重连；已发送的修改请求只能 query，绝不随连接恢复重发。

### 3.2 rewind

1. 业务服务取得当前快照、目标 entryId 和本地草稿/视图 revision。
2. 保存请求记录、锁定冲突入口，只发送一次请求；面板保持原样。
3. runtime 经内部命令取得新鲜 ctx；适配器核对 session、分支、目标和 busy 状态。不自动 abort、不等未来 idle 后突然执行。
4. 使用 pi 公开导航 API。导航到 parent 与导航到 user entry 的语义不同；首条、连续 user、未回复消息必须先验证，不支持则执行前拒绝，不允许多退一条后再报错。
5. 检查 cancelled 和真实分支，持久记录结果，采集操作后快照并回传。持久化失败或副作用无法判定时保留未知，不伪造无副作用失败。
6. IDEA 验证操作关联与本地 revision，按快照提交用户消息投影；恢复草稿时保护用户新输入。迟到结果若远端已继续变化则进入业务冲突，不盲目覆盖。

### 3.3 断联与恢复

- 可证明尚未发送：明确未发送；开始写入后不确定是否送达：观察状态 UNKNOWN。
- 查询使用原 requestId；NOT_FOUND 不意味着肯定没执行。
- 远端历史结果与当前快照分别返回：操作成功过不等于当前分支仍停在那里。
- 终态日志可跨实例查询；执行完成到日志落盘之间崩溃只能 UNKNOWN，不能重做操作补日志。
- 未决期间保护同资源修改入口，允许浏览、复制、草稿编辑及其他会话操作。
- 人工对账只同步已确认的当前状态；必须确认旧执行已终结才能解除锁，不将“关闭提示”解释为取消远端操作。

### 3.4 fork 后续兼容

现有 fork 是“新 Terminal 的 CLI 副本 + 副本内精确 fork”。不能直接在源 Terminal 调用 fork，否则改变产品语义。

后续 ForkWorkflow：

1. 保存源快照及选中完整 turn 证据，创建 PREPARING 目标条目，启动目标 Terminal 一次。
2. 等待能力 READY 和目标快照，不用固定 3 秒 sleep。复制后核对目标 entry/内容，不能假定所有 pi 版本复制都保持 entryId。
3. 在目标提交普通操作 `conversation.forkAtTurn`，使用相同请求/结果/快照结构。
4. PiAdapter 封装 ctx.fork(withSession)；OperationRuntime 的持久 handoff 将原请求结果交给新实例报告。新 session 是结果上下文变化，不新增 fork 专用网络消息。
5. 验证最终快照后将目标转 READY、绑定新 session；源不动，中间副本不被旧事件错误归档。
6. 超时/崩溃保留临时目标，只查询，不重复启动、不重复 fork、不自动删 jsonl。

公共 handoff 只处理“执行跨实例存续”，不处理 Terminal 准备。它使用持久 ticket、单写者交接及新上下文核验，不复用已销毁的 socket/ctx。新 hello、sessionId 改变或相同 tabKey 本身都不是成功证明。

## 4. 风险

| 风险 | 处理 |
|---|---|
| 完整快照很大 | 同机优先简单全量同步；后台解析、背压、可配置宽松资源上限，失败明确返回不完整，禁止按截断快照删历史 |
| 会话采集时变化 | 采集前后核验，快照标识是观察凭据不是全局锁；不一致时不作为修改前置依据 |
| 会话事实与模型有效上下文不同 | 保留原生 entries；不能把活跃分支原文宣称为精确 LLM prompt，投影由 pi 管理 |
| RPC 能力被误当 TUI 接口 | 只借鉴格式；所有执行经交互式 pi 的公开扩展能力 |
| 版本漂移 | PiAdapter 集中适配；未知原生字段保留；不兼容的修改能力禁用 |
| 执行/日志非原子 | UNKNOWN + query，绝不承诺跨进程 exactly-once |
| 草稿或手动 TUI 操作竞争 | 本地 revision 保护、前后快照核验，冲突可见，不强制覆盖 |
| fork 替换实例 | 通用 handoff 与稳定资源锁；不在业务 handler 使用旧上下文 |

验收至少覆盖：三类操作扩展不改传输协议；真实 TUI 无 prompt 污染且编辑器内容不丢；正常 rewind、取消、busy、目标歧义；结果/accepted 丢失；重复结果；执行/落盘/本地提交各崩溃窗口；reload/换绑与迟到结果；隐藏卡片和旧历史迁移；大快照和不完整快照；fork 新实例先握手后终态的顺序。

## 5. 包结构

```text
bridge/BridgeProtocol.kt        协议 DTO、codec、校验
bridge/PiBridgeServer.kt        监听入口与 v1/v2 分流
bridge/BridgeConnection.kt      连接、认证、心跳、背压
bridge/BridgeOperations.kt      请求句柄、日志协调、查询、锁
bridge/OperationStore.kt        请求结果与 handoff 持久记录
conversations/ConversationOperations.kt  rewind 提交、草稿/视图保护
conversations/ForkWorkflow.kt   后续 fork 多阶段业务
resources/bridge/pi-launcher-bridge.ts   单文件安装产物
```

extension 内部封装 Transport、OperationRuntime、PiAdapter、OperationJournal 与 method registry。先保持单文件安装，不为拆模块向用户 extensions 目录散装依赖。

UI 不接触 socket/JSON；OperationRuntime 不操作 Swing；PiAdapter 不重实现 SessionManager。
