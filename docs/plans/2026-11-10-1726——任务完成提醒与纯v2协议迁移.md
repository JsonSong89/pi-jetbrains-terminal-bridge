# Agent 完成提醒与纯 v2 协议迁移

任务结束后通过系统提示音和后台应用图标提醒用户，移除完成弹窗及 v1 通信路径。

## 1. 决策表

| 编号 | 决策 | 结论 |
|---|---|---|
| D1 | 提醒方式 | 声音、应用图标提醒两个独立开关，默认均关闭；移除原有完成弹窗及 `notifyOnAgentEnd` 设置项，不迁移为新开关 |
| D2 | 声音范围 | 开启后正常完成、出错结束各响一次，前后台均生效；用户主动中止不提醒 |
| D3 | 图标提醒范围 | 开启后正常完成、出错结束且 IDE 在后台时请求平台提醒；不抢焦点、不自动打开终端 |
| D4 | 平台约束 | 优先复用系统与 IDEA API；不指定闪烁颜色、次数、持续时间，不设置重复闪烁定时器，不修改 IDE registry 或系统设置 |
| D5 | 声音实现 | 首选 `Toolkit.getDefaultToolkit().beep()`，接受系统定义的音色与音量；不合成音频、不引入音频资产。真实 Windows IDEA 验证系统声音链路有效后交付，不能仅凭调用成功宣称有声 |
| D6 | 图标实现 | 使用 `AppIcon.getInstance().requestAttention(project, true)`，在 EDT 调用；Windows 的闪烁、其他平台的图标行为均交给平台处理 |
| D7 | 完成来源 | 在认证 v2 连接中显式传递 `agent.finished` 事件；不从快照 busy→idle 推断完成 |
| D8 | 完成时机 | 公开 `agent_start` 分配 runId，`agent_settled` 发出完成事件；`agent_end` 仅提供结束原因；工具结束、快照刷新和 bridge 操作终态不触发提醒 |
| D9 | 去重与重连 | 以 `(tabKey, runtimeId, runId)` 去重；不合并不同任务的完成事件；重连不重放完成事件、快照不补发提醒 |
| D10 | 迁移范围 | 移除 extension 的 v1 短连接发送、IDE 的 v1 解析/路由/seq 去重及旧兼容分支；模型、文件变更与会话生命周期的有效能力保留并迁入 v2 |
| D11 | 不支持的旧端 | 不提供 v1 fallback；诊断说明需升级 extension 并重启终端，不伪造完成或会话停止 |

## 2. 对外契约

### 2.1 设置

```kotlin
var soundOnAgentEnd: Boolean = false
var attentionOnAgentEnd: Boolean = false
```

设置页显示两个独立选项：

- `Play a system sound when the agent finishes`：无论 IDE 是否在前台。
- `Request taskbar / Dock attention when the agent finishes`：仅后台有效，表现由平台决定。

删除原完成弹窗选项；保留其他业务错误、警告等通知，不扩大为移除整个通知组。

### 2.2 v2 完成事件

```json
{
  "v": 2,
  "type": "event",
  "event": "agent.finished",
  "runId": "<uuid>",
  "sessionId": "<pi-session-id>",
  "outcome": "completed"
}
```

- `outcome` 为 `completed | error | aborted`；IDE 接受 aborted 但不提醒。
- tabKey、runtimeId 取自已认证且当前有效的连接，不信任事件额外传入的身份。
- runId 在一次 agent 运行期间稳定，不是 bridge operation id；每次运行生成新值。
- 未观察到本实例对应的 agent_start 时，不生成完成事件，不根据 idle 快照补造 runId。
- 事件复用现有队列与资源预算，不进入 operation journal，不增加 request/ack 或耐久重放机制。连接中断可能遗漏当次提醒，明确不承诺离线可靠投递。
- IDE 维护按 tab/runtime 有界的近期 runId 去重集合；实例退休后拒绝其事件。重复完成不重复响铃或请求图标提醒。

### 2.3 其他 v1 能力迁移

- 会话绑定继续以认证 hello、v2 handoff 和有效快照为权威，不再接受 v1 session_changed。
- 工作状态和模型显示使用 v2 快照，不再发送 v1 agent_state/model_changed。
- 文件变更使用认证 v2 `event: "file.modified"`、`path: string`，沿用原有 VFS 刷新与按设置打开文件行为；不同文件事件不得作为最新状态合并丢弃。
- 终端退出由现有终端生命周期处理；v2 连接断开只表示不可达，不等于进程停止或任务完成，不以 v1 session_stopped 兜底。

实施时先更新正式契约 `docs/bridge-protocol.md`，包括事件结构及第 7 节的 v1 退出要求，再修改实现。本文是待实施方案，不代表正式契约或代码已完成迁移。

## 3. 运行流程

1. extension 完成 v2 认证；IDE 关联当前 tab/runtime。
2. agent_start 生成本次 runId，清空本次结束原因。
3. agent_end 读取公开事件中的错误结果；agent_settled 结合 aborted 标记生成 outcome，发送一次 agent.finished，并清除本次运行状态。
4. IDEA 校验连接归属、事件字段和去重键；aborted 到此结束。
5. 读取两个开关：声音开启则调用系统提示音；图标提醒开启且 IDE 应用不活跃则在 EDT 请求一次 attention。判断使用应用级活跃状态，不以某个项目 frame 未激活代替整个 IDE 在后台。
6. 两个提醒通道独立失败，不互相阻断。无完成 balloon、自动聚焦或重连补响。

## 4. 风险与消除方式

| 风险 | 消除方式 |
|---|---|
| 系统静音、音频配置或实际 Toolkit 导致 beep 无声 | 必须在目标 Windows IDEA/JBR 上实测。此前仅看到 IdeToolkit.beep 空实现，不能据此断定本地桌面实际使用该 Toolkit；也不能保证所有环境可发声。若目标环境不可用，实施前调整声音 API 选择，不默默交付无声功能 |
| 系统或 IDE 禁止图标提醒 | 尊重平台设置，接受无效果；不修改 registry，不自行模拟闪烁 |
| 短任务、工具间隙、重连造成漏报或误报 | 使用显式 settled 事件及 runId；不依赖合并快照边沿，重连快照不触发完成 |
| 重复事件或旧实例消息重复提醒 | 连接身份校验及 runId 去重；不同任务分别提醒 |
| 迁移遗漏造成已有能力回退 | 检查全部 v1 发送及路由调用点，覆盖模型更新、文件刷新、会话绑定和终端退出；更新协议测试，删除旧 v1 契约断言 |

验证覆盖：前台/后台完成、错误结束、主动中止、多工具长任务、短任务、重复事件、重连和旧实例事件；纯 v2 下的模型与文件刷新；Windows 实机声音与任务栏行为。CI 不能替代桌面音效和闪烁验收。

## 5. 包结构

- `bridge/`：v2 事件解析、身份验证、完成去重及 v1 传输清理。
- `conversations/`：按会话接收完成事件，移除 v1 遥测边沿表及完成弹窗分支。
- `services/PiFinishNotifier.kt`：读取声音/图标设置，调用平台 API，管理提醒资源生命周期。
- `settings/`：两个新开关的持久化与 UI，移除旧完成弹窗选项。
- `src/main/resources/bridge/pi-launcher-bridge.ts`：生成 runId、发送 v2 完成/文件事件、移除 v1 sender。
