# 会话历史折叠与消息轨道

**一句话定位**：右侧 ToolWindow 的「用户消息历史」区，把超长消息默认折叠为 4 行，并在滚动条右侧加一条按消息顺序等分的窄轨道，使任意一条历史消息最多一次点击/一次按键即可落到头部。

已定的前提（不再讨论）：历史区定位解决的是**空间定位**（消息有顺序、就近往回看），不做按内容搜索；历史只包含用户消息（`PiUserMessage`），不引入 AI 回复。

---

## 1. 决策表

| # | 决策 | 结论 |
|---|------|------|
| D1 | 历史区重建门控 | 状态类刷新（`statusLabel`、combo、按钮可用性、字体）每次事件都执行；**历史区仅在「消息签名」变化时重建**。签名 = `conversationId + messages.size + 末条消息 identity`。`ChangeKind.STATE` 永不触发历史重建 |
| D2 | 折叠呈现 | `JTextArea` 始终持有全文；通过正文组件的固定首选/最小/最大高度裁剪（不依赖 `rows` 的宽度相关首选高度），折叠态为 `COLLAPSED_ROWS` 行，展开态按视觉行数定高。卡片底部显示「展开（剩余 N 字）」/「收起」链接 |
| D3 | 折叠状态存放 | transient，按 `PiUserMessage` **对象 identity** 存于面板内的 `MutableSet<PiUserMessage>`。不落盘、不加模型字段；切换会话或 IDE 重启即清空 |
| D4 | 阈值与上限 | `COLLAPSE_CHARS = 480` 触发「可折叠」；`COLLAPSED_ROWS = 4`；展开态不设行数上限；`text.length > 20_000` 时展开上限 `200` 行并在链接处标注「内容过长」 |
| D5 | 轨道形态 | 滚动条右侧新增 **8px 独立自绘窄条**，不改写/替换 `JBScrollBar`，不拦截滚动条的手势与轨道点击语义 |
| D6 | 轨道几何与交互 | **按索引等分**（第 `i` 条占 `[i*H/N, (i+1)*H/N)`），不是按内容高度比例；视觉只画 3–4px 刻度，命中区为整格；点击 → 该消息头部对齐视口顶部 + 300ms 高亮；高亮「视口顶部所在消息」对应刻度；格高 < 3px 时刻度合并成密度条；`N == 0` 或内容不超一屏时轨道隐藏（宽度归 0） |
| D7 | 滚动策略 | 仅在 `SENT` 事件、或重建**前**采样「已距底 ≤ 视口高度 1/4」时，才滚到底；否则保留锚点（消息 identity + 卡内偏移）并恢复。删除/截断导致锚点消失时优先恢复相邻存活消息。折叠/展开保持卡片底部操作区的视口位置（受边界夹紧约束） |
| D8 | 轨道数据来源 | 轨道只依赖 `N` 与「视口顶部消息索引」，不读卡片 `y` 布局；顶部索引 = `historyList` 中第一个满足 `y + height > viewPosition.y` 的卡片索引 |
| D9 | 键盘入口 | `Alt+↑` / `Alt+↓` 跳到上/下一条消息头部，复用同一 `jumpTo(index)`。绑定在 `historyScroll` 的组件级 `AnAction` 快捷键作用域，适应 IDE 事件分发；单独跟踪目标索引，使尾部无法顶对齐时仍可连续逐条导航。手动滚动后重新从视口顶部同步 |
| D10 | 轨道悬停提示 | tooltip = `HH:mm · 首行前 30 字`（时间格式复用现有 `timeFormat`） |
| D11 | 卡片高度上限 | 不加最大高度、不做卡片内滚动/内嵌滚动条；「任意消息一次可达」由 D6 保证 |
| D12 | 模型与持久化 | 零变更：`PiConversation`、`PiUserMessage`、`PiConversationStore`、`PiConversationService` 的 API 与 XML 结构都不动 |

## 2. 对外契约

### 2.1 轨道组件（新增，`ui/PiMessageRail.kt`）

```kotlin
class PiMessageRail : JComponent {
    /** 消息条数；0 时 preferredSize.width = 0（隐藏）。topIndex 为视口顶部消息索引，-1 = 未知。 */
    fun update(count: Int, topIndex: Int)

    /** 点击某条消息时回调，参数为消息索引（0-based）。 */
    var onJump: ((Int) -> Unit)?

    /** 悬停 tooltip 文案来源；返回 null 表示不显示。由面板注入，避免轨道依赖会话模型。 */
    var titleProvider: ((Int) -> String?)?

    /** 当前高亮的消息索引。 */
    fun setHighlight(index: Int)
}
```

- 命中：`slotIndexAt(y)` 返回 `[0, count)` 内的索引，整格命中；刻度仅作视觉。
- 密度合并：`H / N < 3px` 时每 `ceil(3 / (H / N))` 条画一条，点击仍解析到最近格。
- 不自绘滚动状态、不消费滚轮事件。

### 2.2 面板内部契约（`ui/PiConversationPanel.kt`，全部 private）

```kotlin
private val expandedMessages: MutableSet<PiUserMessage>   // identity-keyed，见 D3
private fun messagesSignature(conversation: PiConversation?): Any
private fun rebuildHistoryIfNeeded(conversation: PiConversation?, event: ChangeKind)
private fun rebuildHistory(conversation: PiConversation?)
private fun jumpToMessage(index: Int)                     // 顶对齐 + 高亮
private fun currentTopMessageIndex(): Int
private fun scrollToBottom()
private fun isNearBottom(): Boolean

```

### 2.3 服务层事件解释约定（不改服务代码）

| ChangeKind | 面板行为 |
|---|---|
| `SENT` | 重建历史（签名必然变化）+ 按 D7 决定是否滚到底 |
| `STRUCTURE` | 签名变化才重建卡片；滚动按 D7 |
| `STATE` | 只刷状态文案/combo/按钮与轨道高亮，**不重建历史** |
| `DRAFT_APPENDED` / `FOCUS_INPUT` | 不重建历史，只处理焦点与草稿 |

## 3. 运行流程

### 3.1 事件到达（EDT）

1. `PiConversationService` → 面板 listener → `SwingUtilities.invokeLater { refreshUi() }`。
2. `refreshUi()`：
   1. 采样 `wasNearBottom = isNearBottom()`、`anchor = (topIndex, offsetInCard)`（重建前，见 D7）。
   2. 刷新 combo 模型、`statusLabel`、按钮可用性、字体。
   3. `rebuildHistoryIfNeeded(active, event.kind)`：签名未变则跳过卡片重建，仅 `rail.update(N, currentTopMessageIndex())`。
   4. 签名变化 → `rebuildHistory`：重建卡片 → `historyList.revalidate()` → `invokeLater` 内恢复 `viewPosition`（或按 D7 滚到底）→ `rail.update(...)`。

### 3.2 卡片构建与折叠

1. 正文组件 `rows = if (collapsed) COLLAPSED_ROWS else visualLineCount(text, font, width)`，并将 preferred/minimum/maximum height 固定为行数 × `rowHeight` + insets，确保实际布局后不会按全文自动撑高。
2. 折叠判定：`text.length > COLLAPSE_CHARS && message !in expandedMessages`。
3. 卡片底部动作区左侧加链接按钮：折叠态「展开（剩余 N 字）」，展开态「收起」；`N = text.length - COLLAPSE_CHARS`。
4. 点击链接 → `toggleExpanded(message)`：记录卡片底部操作区相对视口的位置，切换后恢复该位置（受滚动边界夹紧约束），使展开/收起链接尽量保持在原处。
5. 正文不绑点击（避免破坏 `JTextArea` 的文本选择）。

### 3.3 轨道点击

1. `slotIndexAt(y)` → `index`。
2. `jumpToMessage(index)`：`viewPosition = Point(0, card.y)`（夹紧到 `max(0, maximum - viewportHeight)`）。
3. 目标卡片 300ms 高亮（背景淡化），`rail.setHighlight(index)`；滚动/重建后由 `currentTopMessageIndex()` 重新计算高亮。
4. 不自动展开目标卡片。

### 3.4 键盘

`Alt+↑` / `Alt+↓` → 从独立导航目标索引（无目标时取 `currentTopMessageIndex()`）推进一条，再调用 `jumpToMessage(index)`；边界处保持目标不变；实际手动滚动后清除目标并重新同步。`Shift+Alt+↑/↓` 不做。

## 4. 风险与消除

| # | 风险 | 消除方式 |
|---|------|----------|
| R1 | 视觉行数测量（`rows` 只认行数、不认 wrap；现有 `lines().size` 对单行长文本是错的） | 封装 `HistoryMetrics.visualLineCount(text, font, wrapWidth)`，按 `(text identity, font, width)` 记忆化；宽度或字体变化时失效。实现二选一：沙箱先验证 `area.setSize(width, Short.MAX_VALUE)` 后 `getPreferredSize().height` 是否已反映 wrap；不成立则改用 `java.awt.font.LineBreakMeasurer` |
| R2 | 折叠/展开导致视口跳动 | D7 的高度差补偿；补偿必须在同一次 EDT 任务内完成，避免先重绘再修正 |
| R3 | 轨道点击被 `STATE` 重建作废 | D1 与轨道同批实施；`STATE` 不重建历史，点击结果能保留 |
| R4 | 重建前「是否在底部」判定失效 | 必须在 `rebuildHistory` **之前**采样（见 §3.1 步骤 2.1） |
| R5 | 后续有人把等分映射「优化」成内容比例 | 决策表 D6 明确禁止；本文件即为约束出处 |
| R6 | 键盘绑定与其他 IDE 快捷键冲突 | 只在 `historyScroll` 的输入映射内绑定（`WHEN_ANCESTOR_OF_FOCUSED_COMPONENT`），不注册全局 `AnAction` 快捷键；焦点在编辑区时不受影响 |
| R7 | 折叠后底部切半行 | 折叠态固定行数，允许半行裁剪；不做渐隐自绘（成本/收益不划算） |


## 7. 审查后的实现约束

- `JTextArea.rows` 不是高度上限：正文显式覆盖首选、最小与最大高度；折叠为 4 行，超长展开最多 200 行，普通展开按视觉行数定高。
- 卡片列表配套保存渲染消息快照。删除后捕获锚点读取旧快照，不能用旧卡片索引读取已修改的模型；锚点被删时保留邻近存活消息的位置。
- 收展保持卡片底部操作区的视口位置（受滚动边界夹紧约束），而不是保持卡片顶部。宽度/字体改变重测时恢复顶部消息锚点。
- 键盘导航单独保存目标索引，避免尾部无法顶对齐时连续向下卡住；实际滚动变化重置导航目标。轨道持续高亮始终表示真实视口顶部，目标反馈由卡片短暂闪烁承担。
- 延迟布局恢复带重建代数检查，旧重建任务不得修改新列表的滚动位置。
- 快捷键使用绑定于 `historyScroll` 的组件级 `AnAction`，适应 IDE 事件分发；不注册全局快捷键。
